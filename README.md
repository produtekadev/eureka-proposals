# Eureka Proposals

Client proposals for Eureka, built as single-page websites from one template.

## How a proposal gets made

Use the skill in `.claude/skills/eureka-proposal/` (ask Claude: "make the proposal for <client>"). It:

1. Reads the discovery transcripts (Circleback).
2. Shows what the client asked for next to what we recommend, and agrees the focus with you.
3. Proposes phases with prices, durations and Essential / Recommended / Optional tags, and waits for your OK.
4. Writes `proposals/<slug>/proposal.json` and runs `python3 build.py <slug>`.
5. Shares a preview, then publishes to `proposals.eureka.ceo/<slug>` and logs it in Notion.

## Structure

- `proposals/<slug>/proposal.json`: a proposal's content (schema: `.claude/skills/eureka-proposal/references/content-schema.md`).
- `proposals/<slug>/index.html`: generated by `build.py`. Don't edit by hand.
- `proposals/demo/`: fake client (Acme Studio) showing every section.
- `proposals/federico-gonzalez/`: hand-built original, already shared with the client. Don't regenerate or edit.
- `proposals/api/accept.js`: runs when a client accepts. Emails them the payment details and kickoff link (copy to the team), optional Slack alert.
- `template/`: design system (`design.css`, `proposal.css`), navigation, scope builder, logo, team photos.
- `components/accept/`: the accept block (form, payment details, kickoff).
- `data/team.json`, `data/company.json`: team, bank accounts, kickoff link, terms. **`company.json` is demo data until replaced.**
- `build.py`: `python3 build.py <slug>` or `python3 build.py --all`.

## Deploys

- **proposals.eureka.ceo**: Vercel project `eureka-proposals` (to create), root directory `proposals`. Each folder is a page, e.g. `proposals.eureka.ceo/demo`. Environment variables: `RESEND_API_KEY`, `EMAIL_FROM`, `TEAM_EMAIL`, optional `SLACK_WEBHOOK_URL`.
- **trolley.eureka.ceo**: Vercel project `eureka-propuesta-federico`, root directory `proposals/federico-gonzalez`.

Every push to `main` deploys both. Branches get preview links.
